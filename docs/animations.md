# 应用动画

更新日期：2026-10-24。本文记录当前动画实现、生命周期约束和验证结果。

## 交互行为

| 交互 | 当前行为 |
| --- | --- |
| 侧栏 / 页面导航 | 新页面淡入并小幅滑入，返回使用相反方向；重复进入同一页面不重跑生命周期 |
| 页面返回 / 换根 | 列表停在离开前的位置；详情返回的共享封面落点因此仍在视口里，能照常往返 |
| 侧栏选中高亮 | 胶囊从旧项滑到新项（260 ms）；重复点同一项不滑，进歌单详情等无对应项的页面时收起，窗口缩放、侧栏收展与菜单区滚动直接落位 |
| 页内 Tab | 胶囊选中背景移动并适配宽度，内容按页签方向淡入 |
| 设置页分类栏 | 与侧栏同一实现（`Controls/SelectionPill`）：选中底在分类之间滑动，内容小幅向上进入；分类栏不折叠，也没有收展与滚动之外的落位场景 |
| 发现页横向卡片 | 旧内容沿翻页方向滑出、淡出，再替换当前页；新内容从对应方向进入，移动范围由视口裁剪 |
| 点击单曲 | 播放确认后，点击位置的封面沿加速下坠轨迹缩入播放条；首播等待播放条封面完成有效布局 |
| 歌手 / 歌单 / 专辑详情 | 来源头像或封面移动、缩放到页头，返回时缩回原页面对应的可见卡片 |
| 排行榜 / 乐库 | 与上一条同一套：点榜卡片进榜详情、点乐库大类进分类页，封面放大到页头，返回时缩回原卡片 |
| 排行榜展开分组 | 装回来的卡片淡入并小幅上移（120 ms）；**收起不做** —— 收起要让下一组立刻上移，再给旧卡片做退场会和重排叠在一起 |
| 封面图解码 | 封面解码完成时淡入（120 ms），代替「先露底色、图到了硬切」。已缓存、容器复用同一张已解码的图、以及源为 `null` 三种情况都直接落位，不淡入 |
| 多歌手选择框 | 在弹窗关闭前捕获选中的头像，再移动、放大到歌手详情页头部 |
| 播放条进入歌词页 | 封面先飞；顶栏、传输控件、歌词按 45% / 60% / 80% 的节奏依次淡入，封面落位前不显示空槽与倒影 |
| 歌词页收起 | 大封面缩回播放条，歌词内容和背景淡出；封面交接结束后卸载页面。先收树再复位视觉状态，避免末帧闪回（2026-10-24） |
| MV 收起 | 页面向下退场并淡出，直接返回原常规页，跳过栈中的歌词页；没有封面缩小或画面缩放 |
| 播放队列抽屉 | 拉开时行列表先不显示，定位到正在播放那一行之后淡入（120 ms）；定位赶不上布局时最多晚几帧露面，中间态看不到 |
| 播放队列删单曲 | 被删的行向上轻移 6 DIP 并淡出（170 ms），动画结束后才从队列移除；其余行由增量删行补位 |
| 通知条 | 从底边轻抬 6 DIP 并淡入（220 ms），收起反向淡出；显示中换文案不重播入场，收起推迟一拍以免换条时闪一下 |
| 氛围背景变色 | 封面切换时三个主色在 650 ms 内插值过渡，每 40 ms 重绘一帧；连续切歌从当前显示色接着过渡，系统关闭动画时直接切换 |
| 主题切换 | 正常应用主题后，独立的轻微遮罩在 650 ms 内淡出，保留实时内容和完整主题样式 |

上述新增动画遵循 Windows 的动画开关。关闭动画时直接完成交互。动画不创建离屏列表项，不强制滚动用户的列表；返回时把列表放回**离开前的位置**不属于这一列 —— 那是恢复用户自己滚到的位置，见下文。

## 共享封面与首次布局

`Motion.SharedCoverKey` 用模型类型和 id 关联同一元素，例如 `artist:10208`、`playlist:100169846`、`track:125609`。详情页页头元素命名为 `DetailCover`。圆形头像和圆角封面分别保留对应裁剪，裁剪尺寸考虑宿主缩放。

**给一个新页面接上共享封面要同时做三件事，缺一不可**：来源卡片挂 `SharedCoverKey`、目标页页头命名为 `DetailCover` 并挂同一个 key、`CoverTransitionAnimator.DetailKey` 里登记这个页面类型怎么算出 key。第三件最容易漏 —— 目标页刚构造、`x:Bind` 还没求值，那一刻只能从页面的 ViewModel 直接取 key，漏了就是「卡片和页头都配好了却什么都不发生」。key 本身写在 `Formats` 里，字符串形如 `<类型>:<id>`；id 是字符串的场合（乐库分类）不能沿用 `id > 0` 判空。

首次进入时，目标页面尚未触发 XAML 的 `Loading`，导航直接从页面模型取得封面标识；等 `Loaded` 后**再等目标完成布局**才测量位置。`Loaded` 早于首次 arrange 是常态，此刻页头封面还没有尺寸，直接按「不可见」判会让整段交接被静默跳过（曾表现为「有时候点歌单没有封面放大的动画，过一会再点又有了」），所以导航与下坠两条路径都等待目标可见：三条通道（页面 `Loaded`/`SizeChanged`、外壳 `LayoutUpdated`）加一次低优先级入队检查，目标两秒内仍未就绪时跳过动画、只保留内容过渡。下坠那条路径还额外要求首播的播放条曲目信息已完成布局（`Started` 通知早于有效布局），因此保留点击快照再等。这两项等待都不阻塞音频播放。

共享层同时只保留一张飞行封面。交接期间隐藏来源和目标的实际图像，完成或取消后恢复；图像源变化、元素卸载和窗口尺寸变化也会恢复可见性。新的请求终止上一轮过渡。

返回只使用仍属于原页面、模型身份匹配且当前可见的落点。**列表在返回时先回到离开前的位置**（`ScrollMemory`，见下节），原来那张卡片因此仍在视口里，落点通常都成立；只有卡片确实已被回收、数据被移除，或恢复窗口内没等到时，才退回普通内容过渡。多歌手弹窗关闭后的头像不再作为返回目标。

### 歌词页入场：封面先行，内容分层（2026-10-24）

从播放条进入歌词页时，页面内容此前整块随沉浸宿主一起淡入，看起来是「页面先展开、封面再飞进来」。
现在按 LyciaMusic（AMLL 详情页）的节奏分层：封面是唯一先行的元素，其余内容按封面飞行（520 ms）的
**45% / 60% / 80%** 依次进入，每层再各用 400 ms 淡入并轻微上移。

| 时刻 | 内容 |
| --- | --- |
| 0 ms | 只有背景淡入与封面放大；歌词页空槽底色暂清空、倒影隐藏，画面里不出现第二个封面 |
| 234 ms | 顶部标题栏与歌名 / 歌手 |
| 312 ms | 底部传输控件、进度条、频谱 |
| 416 ms | 歌词画布 |
| 560 ms | 恢复封面槽底色，倒影淡入 |

判断依据是 `CoverTransitionAnimator.HasLyricsEntrance`：只有「播放条封面 → 歌词页大封面」这条路径才分层；
没有共享封面的普通进入仍走原过渡。图层藏在 `LyricsPage.BeginCoverEntrance`，
离场或中途返回时由 `OnNavigatedFrom` 取消计时器并恢复封面槽与倒影。

## 返回时的滚动位置

换页是把宿主的 `ContentControl.Content` 从旧页换成新页：页面实例留着，但滚动位置属于列表控件的模板内部状态，重新挂上树时从 0 开始。`ScrollMemory` 在离场前记下页面上各滚动容器（列表记容器实例本身，独立 `ScrollViewer` 记自己）的像素偏移，挂回来后在头几帧用 `ChangeView` 放回，最多重试 30 帧或 700 ms。

只恢复呈现状态：不重建列表、不清 `ItemsSource`、不调用 `ScrollIntoView`，所以既不动数据源，也不会挪动用户没滚过的那部分。列表**内部**（行模板、条目）不再往下走 —— 那些容器会被虚拟化回收，记下来的位置会张冠李戴。歌词页与 MV 页不参与：它们换的是沉浸宿主，常规页留在外壳里当背景，位置本来就没丢。

**落位之前这些容器不显示。** 否则位置虽然对上了，用户看到的是列表先按「顶部」画一帧、再跳到原位置 —— 那一下「闪」比停在顶上还刺眼。做法是先把布局赶出来（`Loaded` 早于首次 arrange，这一刻列表还没有可滚范围）让偏移落在首帧上，赶不上就在 250 ms 内逐帧重试，超时按当前落点淡入显示，此后不再动它（列表已经显示出来还在挪位置，是另一种毛病）。播放队列抽屉打开时的定位用同一套遮挡，见 `docs/play-queue.md` §14.1。

共享封面动画要**等滚动落位之后**才启动（`NavigationService.PlaySharedCoverAsync`）。不等的后果有两种：列表还在顶上时等不到落点，整段动画被静默跳过；或者落点按列表顶部的坐标量出来，封面飞到半路停下。侧栏换根（发现 / 我喜欢的 / 乐库）走同一条路径，因此也回到原位置。

**返回时不要把列表重拉一遍。** 位置恢复只在「列表本身没被重建」的前提下成立：`PagedList.ReloadAsync` 会先 `Items.Clear()` 再重填，滚动位置归零、容器全被回收 —— 既回不到原处，共享封面也找不到落点，整段退回普通页面过渡。所以「详情页里改过的状态，返回时同步回列表」要用增量方式（`PagedList.Remove`），不要用重拉。2026-10-14 修的「关注的歌手」返回即失败就是这个成因：它在 `OnNavigatedTo` 里无条件重拉，第一页看不出来（项还在顶部），翻过一页必现。

**两次「重建」的差别在清空与重填之间有没有让出一轮布局。** 实测：「最近播放」换根回来位置**不丢**，虽然它每次进入都会 `Tracks.Clear()` 再重填 —— 因为它清空之后是**同步**把条目加回去的，中间没有 `await`，列表从没以「空」的状态量过一次。而 `ReloadAsync` 是 `Items.Clear()` 之后等一次网络请求，那一轮布局里列表是空的、可用高度归零，偏移被夹到 0，之后填回多少条都回不去。机制由这两处代码的差别推得，没有逐帧验证。

页面 `OnNavigatedTo` 里「已加载就不做事」的 `EnsureLoadedAsync` 最稳，返回路径优先用它。

## 导航与 MV 生命周期

播放请求即时处理，普通页面在完成内容切换后播放入场动画。沉浸页离场等待视觉交接结束，再执行页面生命周期和内容卸载；过渡中重复返回或选页时只提交最后目标。

常规页保留在外壳中作为歌词/MV 展开、收起的背景，导航通知仍遵守先离场、后进场的顺序。MV 仍先执行 `VideoSurface.SetMediaPlayer(null)`，再释放播放器。

**歌词与 MV 互切保持全屏（2026-10-24）。** 两者共用同一个沉浸宿主，窗口没有离开沉浸态。
旧页离场走的 `ExitImmersive` 只在「下一站不是沉浸页」时才恢复进入全屏前的窗口；
互切时保留系统 `FullScreen` 呈现器与保存的窗口位置，新页进入时重新同步全屏图标与占位。
从任一沉浸页回到常规页，才把窗口恢复成进入全屏前的状态。

MV 的“退出 MV”调用 `ExitImmersiveToShell`，使用 `GoBackTo` 跳过栈中的沉浸页，只提交一次返回。不能逐层调用 `GoBack`：经过歌词页会再次触发歌词封面回位。“只听歌”的逐级返回入口保留原语义。

## 主题过渡与资源约束

主题样式由 `ThemeResource` 正常解析。遮罩使用私有 `CompositionColorBrush` 和独立 `SpriteVisual`，以旧主题色的 18% 强度柔和退场；背景、文字、边框与氛围背景的资源值由主题本身管理。

实现必须保留以下约束：

- 不以资源字典中的共用画刷或控件颜色属性作为动画目标，避免污染浅色、深色和高对比度样式。
- 不创建整窗 `RenderTargetBitmap`，避免栅格化开销和动态内容被截图定格。
- 不动画整窗透明度、缩放或位移，避免干扰歌词、频谱、封面飞行和页面切换。
- 先写入动画终值作为底值，再启动显式动画；启动后再写同一属性会提前终止动画。
- 遮罩常驻独立合成层，XAML 首次布局和主题资源更新不会覆盖其透明度动画。
- 侧栏与设置页分类栏的选中高亮块画在列表**之下**（`Controls/SelectionPill`，块放在列表之前的 Canvas 里），依赖宿主底色透明：侧栏靠 `Theme.xaml` 把 `NavigationViewDefaultPaneBackground` 等四个键覆写成透明，分类栏靠 `BodianSettingsRail` 不设底色。宿主若改回不透明底，块会被盖住 —— 症状是「没有高亮」，那时把图层挪到列表之后，代价是底色必须永远半透明。两处都用 `SelectionPillBrush`（高对比度为透明，那一档保留系统自带的选中底，块不参与），色号与 `NavigationViewItemBackgroundSelected` 一致。
- 新请求、卸载或关闭时取消遮罩；窗口按钮配色与托盘更新合并为一次低优先级任务，深浅两版图标复用至窗口关闭。

先前的整窗快照造成动态画面定格；直接动画画刷 `Color` 引发 XAML 未处理异常，共用画刷重复目标和资源覆盖又造成过渡失败及浅色样式回归。最终实现完全撤回画刷颜色动画，以独立合成层隔离主题过渡。

- `共享封面回退`：来源或目标不可见，使用普通页面过渡。
- `滚动位置记录` / `滚动位置恢复`：离屏前记下几处偏移；挂回来后还剩几处没落位（剩的多说明这一页的可滚范围没量出来）。
